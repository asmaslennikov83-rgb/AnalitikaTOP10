# Telegram-бот «Воронка продаж по WB»

Первая версия. Excel по команде, без визуального интерфейса и расписания.

## Запуск на хостинге

В корне проекта находятся package.json и index.js. Установка зависимостей: npm install. Команда запуска: npm start (или node index.js). Используйте Node.js 22 или новее.

На BotHost задайте TELEGRAM_BOT_TOKEN, TELEGRAM_USER_IDS, WB_AUTHORIZEV3_1, WB_AUTHORIZEV3_2 и REPORT_START в переменных окружения. Файл .env не требуется. Заполните cabinets.json для обоих кабинетов. После загрузки запустите сервис средствами хостинга. Автоматический перезапуск после остановки или перезагрузки сервера управляется настройками хостинга; сам проект их не изменяет. Используйте один экземпляр сервиса.

Для локального запуска с файлом .env используйте node --env-file=.env index.js или start.cmd. Обычный npm start читает только переменные окружения.
## Первичная настройка

1. Установите Node.js 22 или новее с npm.
2. В папке проекта выполните `npm install`.
3. Скопируйте `.env.example` в `.env` и заполните:
   - `TELEGRAM_BOT_TOKEN`: токен своего бота от официального @BotFather.
   - `TELEGRAM_USER_IDS`: числовые ID разрешённых пользователей через запятую. Только личные чаты.
   - `WB_AUTHORIZEV3_1` и `WB_AUTHORIZEV3_2`: значение заголовка Authorizev3 из собственного кабинета, без добавления Bearer, если его нет в исходном значении.
   - `REPORT_START`: первое число начального месяца.
4. Укажите названия кабинетов и их предметы в `cabinets.json`. Второй кабинет пока без предметов: заполните его список перед запуском. Файл subjects.json больше не используется. ID 940 и название фильтров взяты из предоставленного примера. Остальные ID нужно получить из параметров отчёта WB; они не выдумываются.
5. Локально выполните `node --env-file=.env index.js`. На хостинге — `npm start`. Компьютер должен оставаться включённым. Запускайте один экземпляр бота; webhook у этого бота должен быть отключён.
6. В Telegram отправьте `/start`, затем `/report 2026-01`.

Токены храните локально в `.env`; не пересылайте в чат и не публикуйте. Бот не принимает токены через Telegram.

## Что в Excel

Команда /report обрабатывает оба кабинета и присылает отдельный файл для каждого. Ошибка одного кабинета не останавливает другой. Название кабинета есть внутри файла и в подписи, ID — в имени файла. Каждый предмет получает отдельный лист. В нём: месячные итоги воронки по пяти группам; ежедневная воронка текущего месяца; лидеры и схожие продавцы для каждого периода; общие заказы предмета. Пропущенное поле остаётся пустым, не заменяется нулём. Все даты имеют явные границы; текущий день исключён по ограничению кабинета WB.

Проценты и медианы берутся из готовых агрегатов WB, не суммируются. Суммы из списков продавцов помечены приблизительными, в том числе сумма собственного магазина в таком списке. Собственная точная сумма находится в группе «У вас». Названия продавцов не используются как уникальный ID; строки с одинаковым названием сохраняются. Дневной рейтинг отражает состав списка за конкретный день, а не постоянную панель одних и тех же конкурентов.

Верхний рейтинг магазина и доли заказов отдельными полями в присланном JSON не подтверждены. Бот не вычисляет их приближённо. Поле effectiveness.percent выводится с исходным названием, поскольку его смысл не подтверждён.

## Ограничение интеграции

Использован фактически наблюдавшийся POST-запрос кабинета:
`https://seller-content.wildberries.ru/ns/analytics-api/content-analytics/api/v2/sales-funnel/seller/comparisons`

Тело: subjectID, skipDeletedNm=false, start, end. Это внутренний интерфейс кабинета, не подтверждённый публичный API. Авторизация одним Authorizev3 — непроверенная гипотеза: кабинет может требовать дополнительные параметры сессии. Не выполнено ни одного живого запроса с учётными данными. Возможны истечение токена, изменение схемы, ограничения периодов и частоты. Бот не обходит ограничения и не обновляет авторизацию автоматически. При 401/403 нужно проверить доступ локально. Секреты не записываются в сообщения об ошибках.

Для начальной проверки используйте текущий месяц и один предмет. При необходимости срок доступной истории уточняется реальными ответами WB. Запросы последовательные, с задержкой и ограниченными повторами при 429/5xx. Файл отправляется только после успешного сбора всех периодов; постоянного кеша и восстановления незавершённой работы пока нет.

## Проверка

`npm test` проверяет даты, високосный год, имена листов, безопасный текст и отказ при ошибке WB. Полная проверка Telegram → WB → Excel → Telegram требует локально заполненных токенов. Без них бот не считается подключённым или запущенным.
